# Contributing to OpenTrust

OpenTrust is currently at the pre-prototype stage. Discussion, documentation improvements, and scoped test proposals are welcome.

## Before contributing

1. Open an issue describing the problem and why it matters to small organizations.
2. Use synthetic datasets and isolated environments.
3. Keep changes small, testable, and documented.
4. Explain assumptions, security boundaries, and known limitations.
5. Do not submit proprietary employer code, confidential records, credentials, or unlicensed third-party material.

## Future code contributions

When the initial Python package exists, contributions should include automated tests, installation instructions, and reproducible evidence for each reported behavior.

## Community feedback

We especially welcome input from nonprofits, independent developers, small organizations, and technical volunteers who can explain what makes a security report usable in practice.

## Conduct

Be respectful and constructive. Do not share sensitive information in public issues.
