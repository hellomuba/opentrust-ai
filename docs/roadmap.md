# OpenTrust roadmap

This is a proposed development sequence. No milestone is claimed complete unless accompanied by working code and tests.

## Phase 1: Demonstrate one meaningful check

- Define synthetic document fixtures and access policies.
- Implement a small, isolated demo agent.
- Add authorized and unauthorized document-access cases.
- Produce a machine-readable and human-readable finding.
- Document test limitations.

**Definition of done:** Another developer can run the test locally and reproduce the result.

## Phase 2: Expand controlled scenarios

- Add prompt-injection tests involving lower-trust documents.
- Add synthetic sensitive-data exposure checks.
- Improve audit traces and remediation guidance.
- Publish automated test results.

## Phase 3: Validate usability

- Interview potential nonprofit and small-business users.
- Observe whether participants understand reports and fixes.
- Refine setup, explanations, and documentation.
- Record feedback and actual participation without inventing adoption.

## Phase 4: Open collaboration and maintenance

- Explore integrations for common agent frameworks.
- Publish a responsible community testing handbook.
- Establish contributor review and issue triage practices.
- Assess sustainable maintenance options.

## Evidence to report

Executed tests, reproducible findings, documented limitations, actual contributors, confirmed pilot participants, time needed to run assessments, and user feedback. Planned targets must not be presented as completed outcomes.
